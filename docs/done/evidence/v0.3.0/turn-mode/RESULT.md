## The defect and its fix

`completionRow` was called from `turn.start`. Now `turn.start` only marks the row as due (`rowDue` in `jeeves/hooks/register.ts`); the turn's first main tool result appends it (`sendRow`, after the ledger entry), else the turn-end reading (`session.measure`, which on this build comes only at a turn's end: 8 in the AC-41 200K run's 40 model calls, each right after `turn.complete`). `completionRow` returns false while there is no task of this session to count (e.g. the task's prompt is not captured yet), so the next tool result tries again; the flag is cleared before the await, so parallel tool calls send one row. Still ADR-007 A1's hidden row at the same points (task start, each continuation, every 10 turns, at once after a recognised compaction), sent later within the turn. A first version sent it at the first `session.measure` instead; that turned out to be the turn's end (AC-41 200K run, conversation 3: 18 requests without the row), so it was moved to the tool result. I: `tests/mod/turn-complete.test.ts` AC 1 (the row at the task's first tool result; at the 10th turn a second tool call adds none; a turn without tool calls sends it at its reading). Turn-mode suite: 310 pass. Live check run: US$0.03 (total ST-16.8 spend about US$0.34).
