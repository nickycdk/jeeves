## 5. Engine rules learned in M1 (2.1.319): do not rediscover

1. **The scanner refuses a `$` noun used as a value**: `typeof $.command.run`, `const p = $.process`. Every `$` use must be a direct call `$.noun.method(...)`.
2. **`$.env.get` needs a literal name.** `FsPort.env` takes a fixed `EnvName` union, and `engine-mod.ts` switches on literals. Add new variables there.
3. **`$` may only be passed to functions declared at the top of a file**, or imported from the plugin's own files. A `const fn = async ($) => …` inside `register` fails validation.
4. **Mod tests cannot call `$.fs`/`$.process`/`$.env` themselves.** The test's top-level `$` has no such nouns. A test hook's `$` does, but calls are refused because the test file's scan lists no calls. Drive storage only through the plugin's own hooks (as `probe.test.ts` and `relay.test.ts` do), with `memfs.ts` answering beneath.
5. **The kit's `$.command.run` input needs `origin` and `presentation`** for `tsc` (the runner tolerates them missing). Use the `typed()` helper in `relay.test.ts`.
6. **Gating hooks** (`command.run`, `tool.call`, `prompt.submit`, `classic.Stop`, …) should get `.catch(($, e, next) => next.called ? next(e) : <refusal or answer>)`. Validate lists those without one.
7. `validate --strict` fails without `author` in `plugin.json`. `userConfig` rows (`stateDir`) are accepted and arrive as `options`.
8. `git rev-parse` echoes unknown flags back with exit 0. Old git does not know `--path-format`, so do not use it. Run git with `LC_ALL=C` when matching its messages.
9. Plugin command output is prefixed `sessionrelay:` by the engine. A local command answer costs no model call.
10. All the M0 traps in the original M1 prompt still apply. Most important for M2: no `context` on `$.prompt.submit`; read rotation state before `await next(e)` in `classic.SessionStart`; all writes go through the storage queue; keep state in files.
