- **How the turn run works:** `jeeves/tests/mod/mode.ts` holds `BOUNDARY = 'stop'`. In `turn`, the kit's `test` (`jeeves/tests/mod/kit.ts`) seats an inline **prepend-tier** plugin whose hooks on `classic.Stop`, `classic.SessionStart`, `session.compact`, `prompt.compose` call `next.to(e, 'append')`, as the Team plugin does live. `stop($, msg)` then ends the main turn with `msg` as its answer and returns what Jeeves submitted as `block` (needs `bottom`); the later `turnEnd` of that turn is a no-op; `generating`'s plugin `/clear` waits for that `turnEnd`, then by default ends the old id and takes `sess-2`, `sess-3`, …; `engineClear` sends no SessionStart. `engineTest` = the same without the `/config` row (the four install-seeding files). A test of a Stop-only subject passes `{ stopOnly: '<reason>' }`: 20 such skips, each listed in the turn run's output with its reason.

## 3. Facts worth keeping

- **Test-kit facts (2.1.319):** a test's `on` may register each event only once (a second `on('prompt.submit')` fails the load; `memHost` already hooks `classic.Stop`, `classic.SessionStart`, `session.compact`, `prompt.compose`); inline `plugins` in `test` options take a `tier`; `next.to(e, 'append')` from a prepend plugin skips the user tier and still reaches the test's own hooks. `kit.ts` keeps per-test state in a `WeakMap` keyed by `$`, and `memfs.ts`'s `hostOf` maps `on` to its host.
- **Mode-aware expectations** (instead of skips) are in `assisted`, `handover` (AC-08 step `CLEAR_SCHEDULED`), `continue` (AC-11 context in the continuation), `manual` (the submitted request in the trace), `complete`, `rotate`, `ui`. Pattern: `import { TURN } from './kit.ts'`.
- Turn mode has no gap between "handover saved" and "/clear scheduled" (one turn end), so tests of a user `/clear` or a file change in that gap are Stop-only.
- `carryUndecided` costs one plugin-store read per typed prompt and per `/jeeves` command.
