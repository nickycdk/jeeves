## 3. Epic E17 — v0.3.x: 200K auto-start (P1)

### ST-17.1 Auto-start on 200K windows — M
- **Depends on:** P-1, P-2.
- **Scope:**
  - **Eligibility:** `AUTO_MIN_WINDOW` and `largeWindow` in `src/core/autostart.ts` become ≥ 200K. The reason `200K window at start` becomes `window below 200K at start`, kept in `NOT_WATCHED` and in the hint list (§6.1).
  - **Model switch:** the auto task ends only on a window below 200K (`src/core/machine.ts:265`, ST-13.3).
  - **Threshold:** stays 50% on 200K (`windowThreshold`, D-32), so the grace margin is 60%.
  - **Grace margin check:** the story reads the engine's auto-compaction point on a 200K window from the test kit and checks that 60% is below it. If it is not, it stops and asks.
  - **`/jeeves later`'s cap:** unchanged (90%, or auto-compaction − 5).
  - **Texts:** spec §5.1 item 4, §6.1 and §13; READMEs; PRIVACY.md ("When it records"); first-run notice and hint wording, if they name 1M; troubleshooting.md; CHANGELOG.
- **Tests:**
  - U: `autostart.spec.ts` eligibility table at 199,999, 200,000 and 1M.
  - I: `eligible.test.ts` (200K eligible; below 200K not; a switch from 1M to 200K keeps the task; a switch to below 200K ends it), `autostart.test.ts` (an auto task on 200K, near-threshold at 40%, grace up to 60%), and the hint tests.
  - The mod suite in its three runs.
- **Risk:** under `autoStart on`, the mod host's default 200K window makes more sessions eligible (ST-13.9 noted that almost none were). Those sessions mostly have no git, so few should change. Any change is read and either fixed or given a mode-specific expectation, and the count is reported.
- **AC:** AC-36 and AC-37 amended (200K eligible, below 200K not); every existing AC still passes.

### ST-17.2 `long-task` that one script cannot solve — S/M
- **Why:** in one of five 1M runs, Haiku saw that the 64 modules cycle through six functions, scripted them all and finished at 60K. That run was void (AC-41).
- **Scope:**
  - **Distinct modules:** each module gets its own function, with its own name, its own rule in SPEC.md written in prose, and its own case table. One option is to generate the modules from a list of distinct small specs, with no repeating cycle.
  - **Driver void check:** `tests/pty/ac41.py` marks a run void by itself when one commit holds more than one module, or when a module is committed before its test file was read. It reports that within the first minutes, so a scripted run costs cents, not dollars.
  - The old `long-task` is kept for reproducing v0.3.0's evidence.
- **Tests:** `build-repo.ts` builds it, and its verify fails on the stubs. A unit check: no two modules share a function name or rule text. The driver's void check gets a recorded transcript (`auto-scripted/`) as a fixture.
- **Live:** none.

### ST-17.3 Live check: one auto-started 200K session — M
- **Depends on:** ST-17.1, ST-17.2, P-3, and the maintainer's go-ahead.
- **Setup:** fresh-install state as in D-49, with a separate config folder and a scratch state folder. A **real 200K window**, with no `JEEVES_TEST_WINDOW_OVERRIDE`. The task is typed as the first prompt, with no `/jeeves on`. The new fixture uses its first ~18 modules. Nothing is typed after the task.
- **Pass:** all of the following.
  - The first-run notice appears, then an auto task holding the prompt word for word.
  - At least one rotation, outside the grace period or past threshold + 10.
  - D-45's four parts are met again.
  - NFR-10 grep clean.
  - Spend within US$2.
- **Evidence:** `docs/done/evidence/v0.3.1/200k-auto/RESULT.md`.
