# Changelog

## 0.1.0 (release candidate; dated when tagged)

First public beta. Release notes: `docs/release-notes/v0.1.0.md`. Release artifact: `scripts/release-zip.sh` (reproducible zip + SHA-256), built and attested by `.github/workflows/release.yml` as a draft release; GitHub Actions pinned by commit SHA.

- Security review (ST-9.1, `docs/threat-model.md`, `SECURITY.md`): values read back from `state.json` that become a file path or a git argument are checked for their exact form (ids are safe names, the start commit is hex, the handover reference is `history/handover-NNN.md`), so an edited `state.json` can no longer make Tibbs write a file through `git diff` or reach outside its folder; git runs with `core.fsmonitor` off (other commands a repository's own `.git/config` names, such as filter drivers, still run, as they do for Claude Code's own `git status`). PRIVACY.md now lists messages held during a handover.
- `/tibbs status` shows the mode (full, assisted or unsupported), the managed task if any, its state, context reading (or "unknown"), threshold, rotations, last handover or error, and the state folder. `/tibbs help` lists commands. If `/tibbs` is taken, Tibbs registers `/tibbs` and says so.
- On an unsupported Claude Code version, Tibbs says which version it needs and does nothing automatic.
- `stateDir` setting (in `/config`) chooses where task state is kept; the default is outside any repository.
- `/tibbs on [goal]` starts a managed task. With a goal, that text is saved word for word and sent as the first prompt; without one, your next typed prompt is saved word for word (`task-rev-001.md`). Slash commands are never captured. Nothing is recorded without `/tibbs on`.
- `/tibbs off` stops the task and releases its lock; no file is deleted.
- A task belongs to one session at a time: another running session gets `LOCK_HELD`. Only commands you type yourself can change a task.
- `/tibbs dod <text>` and `/tibbs check <command>` add a task revision (a new `task-rev-NNN.md`, never an edit). Verification commands are stored as text; Tibbs never runs them. `/tibbs task` shows the original prompt, every change since and the current Definition of Done. Text from Claude, other plugins or other sessions never changes the task.
- While a task is on, Tibbs reads the main conversation's context fill (the status line's figure). A missing figure shows as "unknown", never 0%, and triggers nothing. Rate-limit changes never count as context.
- The handover is requested once when context reaches the threshold (default 50%), with one warning 5 points before. Repeated or simultaneous readings past it do not request again. `/tibbs threshold <20-90>` sets it per task.
- Test runs only: `TIBBS_TEST=1` with `TIBBS_TEST_THRESHOLD_OVERRIDE=<n>` uses n% instead; `/tibbs status` then says `TEST OVERRIDE`.
- `/tibbs pause` stops any handover until `/tibbs resume`; the pause is kept across restarts. A pause while a handover is only requested cancels it; during a handover it takes effect once the fresh conversation has the task. Leaving Claude Code normally releases the task's lock, so `/tibbs resume` in the next session works at once (after a crash, after 2 minutes).
- The first `/tibbs on` on a machine explains, in three lines, where task state is kept, that a fresh conversation will start by itself, and how to pause. `/tibbs status` explains the reason code of a stopped task in one line.
- Typing `/clear` during a task pauses it (`USER_CLEAR`) and says so; `/tibbs resume` continues it in the new conversation (the task and its latest handover are sent as the next prompt), `/tibbs off` ends it.
- A disk error while saving a task revision no longer blocks later revisions.
- While a task is on, Tibbs keeps an evidence ledger of the last 200 commands (redacted, exit status) and edited files, from the main conversation and subagents. Recording never changes, delays or blocks a tool call.
- Once a handover is due, the first tool result in the main conversation adds one hidden note asking Claude to finish its current step and stop (once per rotation, never while paused).
- The handover is asked for only when Claude stops with nothing in flight: no background shell, no running subagent (scheduled crons do not hold it up). While work is in flight Tibbs waits; after 3 such stops (or 20 minutes) it pauses the task with `UNSAFE_BOUNDARY` and says why. Interrupting the handover pauses the task (`USER_INTERRUPT`). If Tibbs itself fails at a stop, Claude stops normally and no rotation step is taken.
- Redaction now also covers Stripe keys, key-like names in any case (`aws_secret_access_key = …`) and quoted secrets in JSON or YAML, and no longer masks type annotations such as `password: string`. What is caught and missed is in PRIVACY.md.
- At a safe stop Tibbs asks Claude for a handover, checks it (format, task and rotation ids, size, no secrets, files named as verified exist, branch and HEAD match git, no "passed" claim for a command whose last run failed) and saves it once as `history/handover-NNN.md`, verified by SHA-256, plus a copy in `handover.md`. An invalid handover gets up to 2 retries with the exact problems listed; after that the task stops with `NEEDS_REVIEW` (`HANDOVER_INVALID`) and earlier handovers stay untouched. 
- After the handover turn ends, Tibbs runs `/clear` once (never `--resume`, `--continue` or a fork), and only after checking that the saved handover still matches its SHA-256; a changed file stops the task with `NEEDS_REVIEW` instead. If `/clear` is refused, the handover is kept and the task waits (`ROTATE_UNAVAILABLE`).
- When context crosses the threshold while Claude is idle, Tibbs sends one short prompt ("Tibbs: prepare handover") so the handover starts without waiting for you. An interrupted turn is never nudged.
- At its own `/clear` Tibbs records the ending session once in `sessions/NNN.json` (id, start and end time, context % at start and end) and hands the task and its lock to the fresh conversation. A `/clear` you type while a handover is saved but not yet used pauses the task instead (`USER_CLEAR`).
- The fresh conversation starts with the original task (word for word), its Definition of Done and checks, and the latest handover (re-checked against its SHA-256). Tibbs then sends a continuation prompt by itself, generated from the handover: what was completed, which files changed, which checks ran with what result, what not to repeat, and the exact next actions. No keystroke is needed. If the handover cannot be verified at that point, or the prompt is refused, nothing continues and the task stops for review.
- A message you type while a handover is under way is held, not sent to the old conversation: Tibbs says so, empties the prompt box, and quotes your message word for word in the fresh conversation's first prompt. Slash commands such as `/tibbs pause` still run at once.
- Safety limits: a fresh conversation that is already near the threshold stops the task (`POSSIBLE_LOOP`) instead of rotating again; after 10 rotations a task pauses (`MAX_ROTATIONS`); after 2 failed handovers in a row the next one stops the task (`FAILED`). A rotation that continues resets the failure count.
- Assisted mode: when Claude Code refuses a plugin's `/clear` (or the task already fell back once), Tibbs keeps the verified handover, says "Run /clear, then type /tibbs continue", and `/tibbs status` shows `mode: assisted`. `/tibbs continue` works only in a fresh conversation and continues the task there. The README explains the modes.
- `/tibbs rotate` hands over now, through exactly the same steps as the threshold (handover, checks, `/clear`, continuation). Typed while Claude is idle, it sends the same one-line "prepare handover" prompt to get there.
- Completion: while a task is on, Claude's instructions include a `TIBBS-COMPLETE` block to end the task with. Saying "done" never completes it. The block counts only when every verification command (`/tibbs check`) ran with exit 0 after the last edit and no blocker is listed: then the task is `COMPLETED`, with a one-line summary (rotations, sessions, checks), its lock released and no further rotation. Missing checks get one reminder listing them; still missing, the task stops with `DOD_UNMET`. A task without verification commands always stops there, and `/tibbs done` confirms it (recorded as your decision, not as verified).
- `/tibbs dod` and `/tibbs check` can be typed right after `/tibbs on`, before your first prompt; they are saved as task revisions right after it.
- Tibbs now also reads the context fill after every tool call in the main conversation, so a long turn that fills context is caught mid-turn (the engine reports context only now and then during a turn). Readings use the exact token count, not the rounded percent.
- API errors: when a turn ends on a rate limit, login, billing, overload or other API error, the task pauses with its own code (`RATE_LIMIT`, `AUTH`, `BILLING`, `OVERLOADED`, `API_ERROR`) and a message that says what to do (for a rate limit, when it resets, if Claude Code knows). Tibbs never retries or sends a prompt by itself after one; `/tibbs resume` continues. Such a pause does not count as a failed rotation.
- Compaction (ADR-006): while a task is active, Claude Code's compaction ahead of time (`precompute`) is skipped. `/compact` and automatic compaction are never blocked; after one, Tibbs hands the task over to a fresh conversation (`COMPACTED`), because a compacted context is lossy.
- `/tibbs recover` continues a task that an earlier session left behind (a crash, or leaving Claude Code mid-task), once, in this conversation: the task and its last validated handover go in as the next prompt, with a note to check the repository first when work after that handover may exist. A handover saved just before a crash is picked up even if its state change was lost. Never while another running session owns the task (`LOCK_HELD`, with how long to wait). An unreadable `state.json` is rebuilt from the task's files (the old one is kept). At start, Tibbs names such a task once; the `autoRecover` setting recovers it by itself. The README has a Troubleshooting section.
- Disk errors and moved repositories: when Tibbs cannot write its task files, the task is blocked (`DISK`) with the folder and the fix, the last saved state is kept, and `/tibbs resume` continues once the disk works. Tibbs never continues a task on another branch than its last handover's (`REPO_MISMATCH`): switch back, or confirm with `/tibbs recover --relink`. A repository folder that was moved is found from the new folder by its old path and moved over with `/tibbs recover --relink`.
- Several sessions: a second running Claude Code in the same project that types `/tibbs on` starts its own separate task; the first session's task stays its own (`LOCK_HELD` for any change from elsewhere). Worktrees and other repositories always have separate tasks.
- Test runs only: `TIBBS_TEST=1` with `TIBBS_TEST_CRASH=<point>` stops Tibbs dead at a named point of a rotation, for the crash matrix (`npm run crash:report`).
- The handover instruction now asks Claude to name each file in a `[verified]` bullet by its real path from the repository root, never a placeholder or a `../` path (the checks reject those).
- The command is now `/tibbs` (it was `/relay`), matching the product name. If another plugin or command already owns `/tibbs`, Tibbs registers `/relay` instead and says so.
- Status entry and transition lines: while a task is on, Tibbs keeps one entry in the status area under the prompt (`Tibbs 34%/50%` while watching context, `?` when the figure is unknown; otherwise the state in words, such as `Tibbs: writing handover` or `Tibbs: paused (USER_PAUSE)`), never more than 40 columns. Your own status line is left alone. Each state change adds one dim line to the transcript (`Tibbs: handover requested (THRESHOLD)`, `Tibbs: handover validated, starting fresh`, ...); these lines are not sent to Claude, and tool calls never add one.
- `/tibbs history` lists the task's last 20 state changes (time in UTC, from > to, reason code, context %) and a summary of rotations, sessions and failed handovers, each line within 80 columns. It only reads, and works after `/tibbs off` too.
- `/tibbs status --diagnose` prints a report to paste into a bug report: Tibbs and Claude Code versions, mode and any missing capability with a hint, OS, state folder (where it came from, writable or not), git, the task and its lock. Your home folder is shown as `~`, session ids are shortened and known secret formats are redacted. `docs/compatibility.md` lists the Claude Code versions tested (`npm run compat`).
- Install from the repository's marketplace (`/plugin install tibbs --marketplace nickycdk/tibbs`, or a clone's path). Uninstalling removes only the plugin's settings entry; task files stay until you delete them. `/tibbs purge --task <id> | --project | --all` lists the folders it would delete and deletes them only after `/tibbs purge confirm <code>` within 2 minutes; a running task is never deleted.
- Documentation: the README now covers the problem, requirements, install/update/uninstall, a quickstart, what Tibbs does by itself and when it stops, modes, data and privacy, every command and setting with its default, and an FAQ; plus `docs/troubleshooting.md` (every stop reason with what to type) and `docs/architecture.md`. CONTRIBUTING lists every script; issue and pull-request templates and a code of conduct were added.
