Jeeves 0.4.0 is an update to the 0.3 public beta of the session-continuity plugin for Claude Code. It shows how far a task has come, across handovers, and it keeps watching when Claude says a task is done that Jeeves cannot prove. It is not an Anthropic product.

## New

- **"3/7 tasks done".** When a task starts, Jeeves asks Claude to write its plan as one numbered list, and to mark each step as soon as it is finished:

  ```text
  <<<JEEVES-PLAN
  1. Schema test for both engines
  2. Codex read test
  3. Early quality run
  JEEVES-PLAN>>>

  <<<JEEVES-PROGRESS done=1>>>
  ```

  Jeeves keeps the list with the task. The status entry shows `jeeves: 27%/40%, 1/3 tasks done`, `/jeeves status` adds `Plan: 1/3 tasks done`, and the completion summary names the count. After a handover the fresh conversation gets the list with the finished steps marked, so the count goes on instead of starting over. If the plan changes, Claude writes it again; steps with the same text keep their mark. The count is Claude's own report, shown for you to follow: it never decides whether the task is done.

- **Jeeves is visible in auto-started tasks.** Their status entry used to stay empty until the context was within 15 points of the threshold. It now reads `jeeves: on` until then.

## Changed

- **Claude saying "done" no longer stops Jeeves.** When Claude reports a task done and Jeeves cannot prove it (no check commands, or checks still missing), Jeeves shows a notice and keeps watching. If you disagree and carry on, it still hands over at the threshold. Type `/jeeves done` when the work is done. Before, the task stopped as `Claude says done. Confirm: /jeeves done`, and carrying on in that conversation ran past the threshold with nothing watching.
- **`/jeeves done` works on your running or paused task**, also after your own `/clear`. It never marks done a task another session left behind.

## Known limits

- The plan is only as good as Claude's report. A plan that does not match the work (a "read the spec" step, say) shifts the numbers; Claude usually notices and says so in its handover.
- Ranges such as `done=1-3` are not read; Claude is asked for step numbers.

## Compatibility

`state.json` becomes v5 once a task has a plan, which is nearly every task after Claude's first answer. 0.3.8 and older refuse such a task as too new; 0.4.0 reads every older task, and a task 0.3.8 stopped as `Claude says done` can still be confirmed with `/jeeves done`.
