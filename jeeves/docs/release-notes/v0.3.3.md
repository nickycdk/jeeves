Jeeves 0.3.3 is a small update to the 0.3 public beta of the session-continuity plugin for Claude Code. The fresh conversation now sees why the last command failed, and messages are in plain words. It is not an Anthropic product.

## New

- **Failed-command output in the handover.** The handover's verified facts show the last output lines of failed commands that Jeeves has not seen pass since: at most 20 lines and 1,200 characters per command, for at most 3 commands. Jeeves takes them from the tool result itself and redacts them; a later pass of the same command removes them. Each item says when the command failed and how many edits came after. The lines are quoted and marked as data, never instructions. Searches (`grep`, `rg`, `ls`, … at the end of the line) keep none. Always on; PRIVACY.md lists what is stored.

## Changed

- **Plain words instead of codes.** The line under the prompt, transcript lines and notifications of a stopped task show one sentence that says what to do: `jeeves: Claude says done. Confirm: /jeeves done` instead of `jeeves: needs review (DOD_UNMET)`. `/jeeves status` says the state in words. Codes remain in `/jeeves history`, `/jeeves status --diagnose` and `events.jsonl` for bug reports; `docs/troubleshooting.md` lists each sentence with its code.
- The handover request mentions that failure output is recorded, so Claude does not restate it.
- Internal changes for the Claude plugin directory's checks, with no change in behaviour.

The handover format is unchanged (`v1`). While a ledger command holds output lines, `state.json` is written as schema version 3; Jeeves 0.3.2 or earlier then reports it as saved by a newer Jeeves and changes nothing, and reads it again once the lines are gone.

## What was measured

One live run (Claude Haiku 5.5, a task started with `/jeeves on`): a failing test's output lines were stored, shown in the handover and in the fresh conversation's own transcript, and gone from `state.json` and the next handover after the test passed. The merged handover was 3,456 characters. A separate check confirmed that Claude Code hands the hook stdout and stderr merged in print order (`docs/done/evidence/failed-output/` in the repository).

## Known limits

- **Output above about 30,000 characters is cut by Claude Code before Jeeves sees it**, so the lines kept are then the last ones Claude saw, not the real end.
- A fix checked with a different command (`npx vitest run foo.spec.ts` after `npm test`) leaves the old lines in place; the item's time and edit count show how old they are.
- Everything in the 0.3.2 notes still applies.
