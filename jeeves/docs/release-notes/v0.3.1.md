Jeeves 0.3.1 is a small update to the 0.3 public beta of the session-continuity plugin for Claude Code. It is not an Anthropic product.

## New

- **Auto-start on 200K windows.** A new install now also watches sessions on models with a context window of exactly 200K tokens; 0.3.0 watched only larger ones. On 200K the threshold is 50% (~100K tokens), and an auto task's first 3 turns hold a handover back only until 60%. If a fresh conversation is already within 10 points of the threshold at its first reading (a large CLAUDE.md), Jeeves stops watching that session and says so, as before. `/jeeves status` gives `window below 200K at start` for smaller windows (it said `200K window at start`).
- **Model switch:** an auto task now ends only when the new model's window is below 200K. A switch from 1M to 200K keeps the task and its threshold.
- **Upgrading changes nothing you set.** If you came from 0.2 and never typed `/jeeves auto on`, auto-start stays off. `/jeeves auto off` and the other off switches work as in 0.3.0.

## Fixed (turn mode, accounts in a Team organization)

- A handover request whose turn ended in a refusal or an API error left the task waiting and held every message you typed. A refusal now gets the retry, and an API error pauses the task (`/jeeves resume`).
- A turn opened by a `/loop`, a background notification or another plugin, while Jeeves waited for the handover, used up a handover retry. It no longer counts.
- When Claude Code refused a prompt Jeeves sent, the task stayed mid-rotation with its lock held until you quit. Now an auto task ends, and a task you started gives up its lock so `/jeeves recover` can continue it in another session.
- A turn whose Stop hook did reach Jeeves was judged a second time at its end.
- If Claude Code merged a queued prompt (a `/loop`, a notification) with Jeeves's handover request into one turn, the handover in the answer was ignored and the rotation waited. An answer that carries the handover block is now read. Not yet checked in a live run.
- When Claude Code refused a prompt Jeeves sent during a handover, an auto task ended and the messages you had typed meanwhile were lost. They are now shown so you can type them again.

## Fixed (every account)

- **An unattended task no longer waits because Claude announced its next step.** In the fresh conversation after a handover of an auto task, if Claude stops with no completion claim and nothing running, Jeeves asks it once to carry on, say it is done, or say what it needs from you. Once per conversation, never after you typed there, and never in a task you started with `/jeeves on`. Not yet checked in a live run.
- After a `/clear` you typed paused a task you started, auto-start stayed off in that project for every later session too, while `/jeeves status` said `this session`. It is now off for that session only. The paused task still waits for `/jeeves resume`.

- `/jeeves off` in a session without a task of its own could turn the project's newest COMPLETED or FAILED task into DISABLED. It now only ends a task that is still running or paused.
- After you quit and came back with `claude --resume` (or `-c`), the session ran its task without holding the task's lock, so another session could recover it at the same time. It now takes the free lock back within 30 seconds.
- `/jeeves recover` in a session that runs a task of its own answered only "nothing to recover", even when an interrupted task was waiting. It now names both tasks: `/jeeves off` ends yours, then `/jeeves recover` continues the other.
- A verification command (`/jeeves check`) holding a secret, a double space or more than 300 characters could never be met, so the task always ended in review (`DOD_UNMET`). It is now compared in the same form Jeeves records commands in.

## What was measured

One live run on a real 200K window (Claude Haiku 5.5 with `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`, turn mode on a Team account, a 40-module task, nothing typed after it): the first-run notice, an auto task holding the prompt word for word, then four rotations; every module committed and the checks passed; median growth of about 77K tokens between rotations; about US$0.56 API-equivalent. Two earlier attempts did not finish: one task was too small to reach the threshold, and in the other Claude ended a turn announcing its next step without taking it, so the unattended task waited. Evidence: `docs/done/evidence/v0.3.1/200k-auto/RESULT.md` in the repository.

## Known limits

- **A heavy turn on 200K can come close to Claude Code's own compaction.** In the measured run, the handover turn took the context to 79%, against compaction at about 83.5%. Jeeves acts at a turn's end in turn mode. If Claude Code compacts first, Jeeves hands over after the compaction, as in 0.3.0.
- **Live runs were made on a Team account only** (turn mode). Accounts outside a Team organization use the Stop-hook path, which is covered by the automated suite only.
- **No saving is promised.** 0.3.1 adds no new cost measurement.
- Everything else in the 0.3.0 notes still applies, including going back to 0.2.
