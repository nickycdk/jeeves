Jeeves 0.3.8 is an update to the 0.3 public beta of the session-continuity plugin for Claude Code. It closes a gap in the completion check: a check that passed before files changed outside Claude's Edit and Write tools no longer counts. It is not an Anthropic product.

## Fixed

- **A stale pass no longer finishes a task.** Jeeves already refused a passing check followed by an Edit or Write. A file changed some other way was invisible: `sed -i` or a formatter run through Bash, `git checkout -- file`, `git stash pop`, your own editor. Now, when a check passes, Jeeves stamps the content of every file changed since the task started, and stamps again when Claude says the task is done. If they differ, Claude is asked to run the check again:

  ```text
  - `npm test`: files changed since it passed (not through Edit/Write)
  ```

  Committing the same content, or stashing and popping it, keeps the stamp. Ignored files, any `.claude/` folder and Jeeves's own state folder never count. All git commands are read-only and take no locks. The stamp is taken before a passing check's result goes back to Claude, so that result arrives a git call later; other commands are not delayed by it.

## Known limits

- When two checks each rewrite a non-ignored file on every run (a timestamped report), they keep making each other stale. The message names the other check: gitignore its output.
- Changes to ignored files, permission-only changes, files outside the repository, a submodule moving to another commit and a change behind a symbolic link (it counts by where it leads) are not caught.
- No stamp without git, without a start commit, or past 2000 changed paths; only the edit order counts then, as before.

## Compatibility

`state.json` becomes v4 once a check has a stamp, which is nearly every task in a git repository. 0.3.7 and older refuse such a task as too new; 0.3.8 reads every older task.

## Install

See the README's Install section. Verify the download: `shasum -a 256 -c jeeves-0.3.8.zip.sha256`.
