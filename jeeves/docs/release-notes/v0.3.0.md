Jeeves 0.3.0 is the third public beta of the session-continuity plugin for Claude Code. It is not an Anthropic product.

## New

- **Auto-start: installing is the opt-in (new installs only).** In an interactive session in a git repository, on a model whose context window is above 200K tokens (1M), in a fresh conversation, Jeeves watches by itself: your first typed prompt becomes the task, word for word, as after `/jeeves on`. The first such session says so once. Nothing is recorded before that first typed prompt, and only on this machine; never the transcript. 200K windows stay off for now.
- **Upgrading from 0.2 changes nothing.** Jeeves says once that it can now watch long sessions by itself, and keeps auto-start off until you type `/jeeves auto on`.
- **Turning it off** at every level: `/jeeves off` (this session), `/jeeves defaults auto off` (this project), `/jeeves auto off` (everywhere, kept in the state folder, never in your Claude settings), or the new **Auto-start** row in `/config`. `/jeeves auto` says which one decided. `/jeeves status` says why a session is not watched.
- **Auto tasks** never hand over in their first 3 turns, stop watching when the context is already near the threshold at the first reading or after a switch to a 200K model, end on a `/clear` you type (a task you started with `/jeeves on` still pauses), and recover by themselves after a session closed mid-handover. `/jeeves on <goal>` makes an auto task yours.
- **Cleanup:** an auto task that ended without a single handover is deleted 7 days after its last change, at a later session start. Tasks you started, and tasks with a handover, are never deleted by Jeeves.
- **`/jeeves later`** postpones the next handover by 10 points, up to 90% or 5 points below Claude Code's auto-compaction point. Works in every task.
- **Current goal** in every new handover: one or two short bullets, shown in the rotation line. The fresh conversation gets your own words first, then Claude's summary, labelled as such.
- **A hint instead of silence:** a session that is not watched only because of the upgrade default, a resumed conversation, no git repository or a 200K window gets one notice when its context reaches the point where a watched one would be warned. Once per session, never under `-p` or after you turned auto-start off; silent after 3 hints you did not act on.
- **`/jeeves` alone** is the one command to remember: status, whether this session is watched and why not, and a `Try:` line with the 2–3 commands that fit now (`later | off` during a warning, `resume` when paused, `retry` after a failed handover, `handover` after a rotation, `on` when not watched).
- **The old conversation is one command away:** the rotation line ends with `Previous conversation: claude --resume <full session id>`. Resumed, it can be read but cannot drive the task; `/jeeves status` there says `Owned by another session`.
- **`/jeeves handover`** shows what was carried over: the last handover's file, its Current goal and first next actions. It only reads; a missing or changed file is reported, not printed.
- **A quiet status entry in auto tasks:** empty until the context is within 15 points of the threshold, then `Jeeves 28%/40%` as before. Tasks you started with `/jeeves on` show it from the start.
- A message typed during a handover is no longer quoted in the task's event log (it is still delivered word for word, and removed from `state.json` once delivered).

## Going back to 0.2

- 0.2 refuses a task that 0.3 has touched (`SCHEMA_TOO_NEW`, "update Jeeves") and never rebuilds or rewrites it.
- 0.2 ignores a project's `config.json` when it holds `autoStart` (any other one keeps its threshold and checks), and never reads `auto.json`.
- Only two things you type in 0.2 reach 0.3's files: `/jeeves defaults clear` replaces the project's `config.json` (its auto-start setting, threshold and checks are gone; back in 0.3 the project follows `/jeeves auto` again), and `/jeeves purge` deletes the task folders you confirm, 0.3 tasks included.
- No data is lost either way.

## Known limits

- Claude accounts in a Team organization run in turn mode (README, Requirements): no scheduled crons in the handover's facts, compaction ahead of time not skipped and a compaction noticed only at the next context reading. Live runs on a Team account (2026-11-09, haiku): two rotations in a row with nothing typed, no handover while a permission dialog is open (AC-07), a typed `/compact` followed by one rotation at the next prompt, and auto-start carried over a user `/clear` all passed (`docs/done/evidence/v0.3.0/turn-mode/RESULT.md`). The completion rules reach Claude from a turn's first tool result, but the engine drops them again before the turn's last model call, and in the very first turn of a new `claude` process (before Jeeves knows it is in turn mode) they arrive one turn later; a finished task may therefore stay watched instead of being marked done.
- Claude Code 2.1.319 and later; macOS tested, Linux expected to work.
