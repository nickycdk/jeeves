Jeeves 0.3.2 is a small update to the 0.3 public beta of the session-continuity plugin for Claude Code. It makes handovers remember more and tells you when a task needs you. It is not an Anthropic product.

## New

- **Commits in the handover.** Each saved handover lists the commits made since the task started (`git log`, oldest first, at most 200), next to the files changed since then.
- **The plan, when there is one.** If the task follows a written plan, Claude names it (its file, or its steps) and which steps are done. Without a plan nothing changes.
- **Decisions and dead ends carry over.** Claude is asked to keep every decision, constraint and dead end from the previous handover that still holds, and to list each approach it tried and dropped, with why, under "Do not repeat / do not change". The fresh conversation's start prompt now also lists "Decisions and constraints".
- **A notification when a task needs you.** When a task stops by itself (a handover failed three times, the handover limit, a rate limit, an error) or completes, Jeeves sends a notification through Claude Code's own notification setting. A pause, `/clear` or interrupt you caused does not notify. The notification carries only the state and reason.

## Changed

- The line under the prompt no longer repeats the name: `jeeves: 12%/40%` instead of `jeeves: Jeeves 12%/40%`. The same goes for Jeeves's transcript lines.
- A task Claude reports as done without passing checks now says `Done, unproven. /jeeves done confirms` (it said `Not done: checks are missing.`).

The handover format is unchanged (`v1`), so 0.3.1 reads 0.3.2 handovers and the other way round.

## What was measured

One live run on a real 200K window (Claude Haiku 5.5, a task started with `/jeeves on`, a 40-module fixture with a written plan, nothing typed after it): 7 handovers with no retries, about US$0.51 API-equivalent. Every handover listed the commits since the start, named the plan and its progress, and kept decisions from earlier handovers; a dead end found in the last conversation was recorded. The run was stopped by hand after module 20, when Claude announced its next step and ended its turn; tasks started with `/jeeves on` get no carry-on prompt, as in 0.3.1.

## Known limits

- **The notification was not seen in a live run.** The task in the run never stopped by itself. The automated suite checks that a failed handover sends exactly one.
- **Typing `/jeeves done` also sends a "task completed" notification**, although you are at the keyboard.
- Everything in the 0.3.1 notes still applies.
