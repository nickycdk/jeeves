Jeeves 0.3.6 is an update to the 0.3 public beta of the session-continuity plugin for Claude Code. It shows what Jeeves did for a task, and helps you pick a threshold that fits. It is not an Anthropic product.

## Changed

- **A summary when a task finishes.** Where the transcript said `Jeeves: task completed`, it now says what the task took:

  ```text
  Jeeves: task completed in 3h 20m: 6 handovers, 14 commits, 2/2 checks passed.
  Jeeves: context cleared 180 points (~360K tokens). Cost: $4.10 (1 session unknown).
  ```

  The notification says the first line. The time is wall time from the task's start, so a night away counts. Commits are left out when git cannot say. After `/jeeves done` it says `confirmed by you`. The second line shows only when there is something to say, and a cost Claude Code did not report stays unknown, never $0. If the figures cannot be read, the old line shows. The pop-up `Task … completed after n rotation(s) …` is gone, since the summary replaces it.
- **A hint when a conversation starts with little room.** A fresh conversation is never empty: the system prompt, `CLAUDE.md` and the tool list come first. When a fresh conversation after a handover leaves fewer than 20 points before the threshold, Jeeves says so once per task and names a threshold with about 30 points of room:

  ```text
  Jeeves: this conversation started at 27%, leaving 13 points before the 40% handover. /jeeves threshold 60 gives more room (/jeeves defaults threshold 60 for this project).
  ```

  The suggestion stays within the `/jeeves later` cap (90%, or 5 points below Claude Code's compaction point). Jeeves never changes the threshold by itself.

Nothing new is stored in the task files. The hint's "shown" flag is in Claude Code's plugin store. The handover format (`v1`) and the state files are unchanged, so 0.3.5 and 0.3.6 read each other's tasks.

## Install

See the README's Install section. Verify the download: `shasum -a 256 -c jeeves-0.3.6.zip.sha256`.
